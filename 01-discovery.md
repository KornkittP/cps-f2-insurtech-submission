# Discover — Daily Insurance Operations Dashboard
## Confirmed client findings
Sales waits for IT to manually export spreadsheet reports every morning, consuming roughly one hour per day. There was no existing dashboard. A reusable report would address the original pain; the later interview agreed a dashboard showing new policies, near-expiry policies, customer questions and recent questions for staff triage. Start with a central overview for the highest-authority users; per-agent access is future scope. Data currently comes from spreadsheets and will move to a database later. The daily new-policy file is generated by another department with a consistent template. The client permits policy numbers and agent codes; names and emails must be masked; free-text questions may contain PII. Claude Code was specified for development; design may be AI-assisted. Only files 1–3 are in scope. The assignee confirmed the files are mock data.

## Users and problem
Primary intended viewer: authorized central management/operations. Beneficiaries: sales and IT; staff use inquiry information to decide whether to respond, handle or escalate. IT Head is release decision maker. Actual problem: repetitive reporting and fragmented operational visibility, not simply absence of a dashboard.

## Proposed success measures (not client-approved targets)
- Reconcile all KPI counts with the approved datasets.
- Reduce manual preparation from the reported 60 minutes/day; measure before/after in a pilot. At 22 working days/month, maximum baseline opportunity is 22 hours/month, not verified savings.
- Replace snapshots without double counting; show source periods and meaningful validation errors.
- Verify masking and withholding against synthetic privacy cases; no real data in Alpha.
- IT can run and maintain the deliverable independently.
